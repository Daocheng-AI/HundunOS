# HundunOS v3.0 架构设计

## 整体架构

```
┌────────────────────────────────────────────────────────────────────────┐
│                           应用层 (Shell)                                │
│                      REST API / Web UI / CLI                          │
├────────────────────────────────────────────────────────────────────────┤
│                         扩展层 (Extension Modules)                    │
│          MCP / Search / WorkBuddy / Evolution / Skills               │
├────────────────────────────────────────────────────────────────────────┤
│                         稳定模块层 (Stable Modules)                    │
│  edict / RBAC / Recovery / RecoverableMemory / HealthMonitor /       │
│  PermissionGating / PrivacyShield / AuditLogger /                     │
│  CoworkMonitor / EnvHealthChecker                                     │
├────────────────────────────────────────────────────────────────────────┤
│                           内核层 (Kernel)                              │
│  Core / IntentEngine / ModelRouter / MemoryGraph / AwareSystem /      │
│  SelfAdaptation / RateLimiter / ToolBridge / UpgradeController /     │
│  HealthMonitor / ModuleRegistry / MessageRouter                       │
├────────────────────────────────────────────────────────────────────────┤
│                        基础设施层 (Infrastructure)                    │
│              Storage / MessageBus / PlatformAdapter /                  │
│              Monitoring / ModelRouter                                  │
└────────────────────────────────────────────────────────────────────────┘
```

## 核心模块

### 1. Kernel (内核核心)

**职责**: 系统初始化、模块生命周期管理、事件总线、启动序列

**关键文件**:
| 文件 | 职责 |
|------|------|
| `kernel/core.js` | 模块注册、生命周期管理、事件总线、启动序列 |
| `kernel/module-registry.js` | 模块注册表，管理所有模块的注册与查询 |
| `kernel/message-router.js` | 消息路由器，解析消息并分发给对应处理器 |
| `kernel/tool-bridge.js` | 工具桥接，统一调用外部工具 |
| `kernel/upgrade-controller.js` | 升级控制器，管理版本升级与回滚 |

### 2. IntentEngine (意图引擎)

**职责**: 用户意图识别与解析，支持内建分类器 + 外部配置扩展

**架构特点**:
- 内建分类器：系统类、任务类、搜索类、代码类
- 外部扩展：支持 `config/intents/*.json` 自定义意图配置
- 动态加载：通过 `custom-intents.json` 配置自定义意图

**分类器类型**:
- `system`: kernel_upgrade, system_status, health_check
- `task`: task_create, task_query, task_cancel
- `search`: file_search, web_search, knowledge_search
- `code`: code_generate, code_review, code_debug

### 3. RateLimiter (速率限制器)

**职责**: 防止系统过载，保护核心服务

**机制**:
- **Token Bucket**: 令牌桶算法，控制突发流量
- **滑动窗口**: 滑动窗口算法，平滑限流

**配置参数**:
```javascript
{
  tokenBucket: {
    capacity: 100,      // 桶容量
    refillRate: 10      // 每秒补充令牌数
  },
  slidingWindow: {
    maxRequests: 50,    // 窗口内最大请求数
    windowSize: 60000   // 窗口大小(ms)
  }
}
```

### 4. AwareSystem (感知系统)

**职责**: 多维度感知用户行为与环境状态，辅助决策

**6类感知器**:
| 类型 | 感知内容 | 应用场景 |
|------|----------|----------|
| WORK | 工作任务、进度、优先级 | 任务调度优化 |
| CODE | 代码编写、调试、审查 | 代码生成建议 |
| ANALYSIS | 数据分析、问题诊断 | 智能分析建议 |
| LEARNING | 知识获取、技能提升 | 学习路径推荐 |
| COMMUNICATION | 对话、协作、反馈 | 对话风格适配 |
| ENTERTAINMENT | 休闲、娱乐、休息 | 适时提醒与建议 |

### 5. SelfAdaptation (自适应系统)

**职责**: 根据感知数据动态调整系统行为模式

**4种行为模式**:
| 模式 | 特征 | 适用场景 |
|------|------|----------|
| `heavy_coding` | 深度代码理解、详细审查、重度重构 | 大型代码开发 |
| `heavy_analysis` | 深度分析、推理、问题诊断 | 复杂问题排查 |
| `heavy_learning` | 知识收集、信息整理、深度学习 | 新领域研究 |
| `balanced` | 均衡负载，动态调整 | 日常混合任务 |

**自适应策略**:
- 基于感知系统数据分析
- 基于历史行为模式学习
- 基于任务复杂度评估

### 6. MemoryGraph (记忆图谱)

**职责**: 可恢复的记忆系统，支持记忆蒸馏与长期存储

**核心特性**:
- **短期记忆**: 会话级上下文缓存
- **长期记忆**: 持久化存储，支持检索
- **记忆蒸馏**: 从大量交互中提取关键信息
- **可恢复性**: 记忆快照与恢复机制

**数据结构**:
```javascript
{
  nodes: [
    { id, type, content, timestamp, importance }
  ],
  edges: [
    { source, target, relation, weight }
  ]
}
```

### 7. ModelRouter (模型路由器)

**职责**: AI 模型选择与调度，支持多 Provider 切换

**调度策略**:
| 策略 | 原则 | 适用场景 |
|------|------|----------|
| `COST_FIRST` | 成本优先 | 简单任务、日常查询 |
| `BALANCED` | 成本与质量平衡 | 通用任务(默认) |
| `QUALITY_FIRST` | 质量优先 | 复杂推理、创意任务 |

**核心组件**:
- `strategies/`: 路由策略实现
- `circuit-breaker.js`: 熔断器，防止故障扩散
- `usage-stats.js`: Token 消耗统计

**支持 Provider**: Ollama / Anthropic / OpenAI

### 8. HealthMonitor (健康监控)

**职责**: 10维度全方位系统健康监控

**监控维度**:
```
┌─────────────────────────────────────────────────────────┐
│                    HealthMonitor                        │
├──────────┬──────────┬──────────┬──────────┬───────────┤
│ modules  │  cron    │  edict   │ task_hub │ workbuddy │
├──────────┼──────────┼──────────┼──────────┼───────────┤
│   mcp    │  token   │ errors   │  skills  │ security  │
└──────────┴──────────┴──────────┴──────────┴───────────┘
```

| 维度 | 监控内容 |
|------|----------|
| modules | 各模块加载状态与健康度 |
| cron | 定时任务执行状态 |
| edict | 三省六部系统运行状态 |
| task_hub | 任务中枢调度情况 |
| workbuddy | WorkBuddy 服务状态 |
| mcp | MCP 协议扩展服务 |
| token | Token 使用量与限额 |
| errors | 错误日志与异常统计 |
| skills | 技能加载与执行状态 |
| security | 安全评分与风险评估 |

## edict (三省六部制)

### 设计理念

借鉴中国古代三省六部制，将任务处理流程制度化、职责分离化。

### 核心流程

```
┌─────────────────────────────────────────────────────────────────┐
│                         旨意 (输入)                              │
└─────────────────────────────┬───────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│                    政事省 (Plan - 规划)                          │
│              任务分解、资源评估、方案制定                         │
└─────────────────────────────┬───────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│                   门下省 (Review - 审核)                         │
│              权限检查、风险评估、可行性验证                       │
└─────────────────────────────┬───────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│                   尚书省 (Dispatch - 执行)                       │
│              任务分发、进度追踪、结果汇总                         │
└─────────────────────────────┬───────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│                      六部 (执行)                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 六部职责

| 部门 | 职责 | 现代化对应 |
|------|------|------------|
| **兵部** | 代码工程 | 代码生成、代码审查、调试 |
| **户部** | 数据处理 | 数据清洗、ETL、数据分析 |
| **工部** | 系统与文件 | 文件操作、系统调用、运维 |
| **吏部** | 审核审查 | 权限审核、内容审核、质量把控 |
| **礼部** | 文档撰写 | 文档生成、报告输出、知识整理 |
| **刑部** | 分析审查 | 问题分析、诊断推理、深度审查 |

### 路由器决策

```
                    ┌──────────────┐
                    │   用户输入   │
                    └──────┬───────┘
                           ↓
              ┌────────────────────────┐
              │    白名单快速匹配       │
              └────────────┬───────────┘
                           ↓
              ┌────────────────────────┐
              │    复杂任务判断         │
              └────────────┬───────────┘
                           ↓
         ┌─────────────────┼─────────────────┐
         ↓                 ↓                 ↓
    直接调度           TaskHub接管        简单查询
         ↓                 ↓                 ↓
    六部执行           六部执行          直接处理
```

## RBAC (角色权限系统)

### 角色层级

```
super_admin (100) ─┐
                   │
    admin (80)    ─┤
                   │
  developer (60) ─┼─→ 权限递增
                   │
   analyst (50)   ─┤
                   │
  operator (40)  ─┤
                   │
   viewer (20)   ─┤
                   │
    guest (10)   ─┘
```

### 权限类型

| 权限 | 说明 |
|------|------|
| `super` | 超级权限，可操作所有资源 |
| `admin` | 管理权限，配置与用户管理 |
| `execute` | 执行权限，任务执行 |
| `write` | 写入权限，数据创建修改 |
| `read` | 读取权限，数据查看 |

## AutoRecovery (自动恢复系统)

### 故障类型 × 恢复策略矩阵

| 故障类型 | restart | rollback | retry | fallback | skip | alert |
|----------|---------|----------|-------|----------|------|-------|
| crash | ✓ | ✓ | - | ✓ | - | ✓ |
| timeout | - | - | ✓ | ✓ | ✓ | ✓ |
| error | ✓ | - | ✓ | - | ✓ | ✓ |
| hang | ✓ | - | - | - | - | ✓ |
| memory | ✓ | ✓ | - | ✓ | - | ✓ |
| network | - | - | ✓ | ✓ | ✓ | ✓ |

**恢复策略**:
- `restart`: 重启服务
- `rollback`: 回滚到上一稳定版本
- `retry`: 重试操作
- `fallback`: 降级到备用方案
- `skip`: 跳过失败步骤
- `alert`: 触发告警通知

## 扩展机制

### 创建新扩展

```javascript
// extension-modules/my-extension/index.js
import { EventEmitter } from 'events';

export class MyExtension extends EventEmitter {
  constructor(config = {}) {
    super();
    this.config = config;
  }

  async initialize() {
    this.emit('initialized');
  }

  async execute(task) {
    const result = await this._process(task);
    this.emit('complete', result);
    return result;
  }
}

export function getMyExtension() {
  return new MyExtension();
}
```

### 注册到内核

```javascript
import { MyExtension } from './my-extension/index.js';

kernel.registerModule('my-extension', new MyExtension());
```

## 基础设施

### Storage (存储层)

- **JSON 文件**: 配置与结构化数据
- **SQLite**: 关系型数据持久化
- **内存缓存**: 热数据高速访问

### MessageBus (消息总线)

- **发布/订阅**: 事件驱动的消息传递
- **主题管理**: 按主题分类消息
- **消息持久化**: 关键消息不丢失

### PlatformAdapter (平台适配器)

- **Windows**: Windows API 集成
- **macOS**: Darwin API 集成
- **Linux**: Linux 系统调用适配

## 设计原则

1. **微内核架构**: 核心最小化，功能插件化
2. **事件驱动**: 模块间通过事件通信，松耦合
3. **可恢复性**: 6种故障 × 6种策略的自动恢复
4. **可观测性**: 10维度健康监控，完整日志审计
5. **安全优先**: RBAC + 权限门控 + 隐私防护
6. **自适应性**: 4种行为模式动态切换
7. **职责分离**: 三省六部制，流程制度化
